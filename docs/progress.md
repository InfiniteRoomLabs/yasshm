# Progress

Living status doc. Read first, update at every phase boundary. Last updated: 2026-11-19.

## Current state

- Repo cut from `InfiniteRoomLabs/template-repo` and planned. Phases 0 to 4 have shipped: the full gate; the tenant types, the strict config loader, the policy engine with its guard rails, the append-only audit log, the checked key-file reader and `yasshm config check`; the SSH layer (`internal/sshclient` with pinned host keys, exec, signals, SFTP and the fixed probe); and the job engine (`internal/jobs` on `internal/store`, SQLite: command records, output files with paging, limits, timeouts, kill, restart recovery, shutdown and the janitor). Phase 4 added the authenticator (`internal/auth`: Access token verification with `go-jose`, the cached key set, the guard middleware that audits every decision). Nothing serves anything yet; Phase 5 (the MCP endpoint, the eight tools and `yasshm serve`) is next.
- The plan lives on the branch `feat/yasshm-mvp` here, and the deployment plan lives on a branch of that name in the operator's private infra repo. Nothing has been merged to `main`.
- The build is one cloud session that holds both repositories and runs the whole roadmap, with a fable orchestrator as lead. It is started with both clones on the plan branch, makes its own working branch in each, and does all its work there. A phase is a commit range on that branch (`GOAL.md`, *How a phase lands*).
- Planning artifacts are in place: the design spec (`docs/superpowers/specs/2026-11-18-yasshm-design.md`), `GOAL.md` (targeting Phase 0, with the kickoff prompt), the five work orders (`docs/phases/_templates/`), and the LikeC4 model of the planned system (every component is tagged `#planned` until its phase builds it).
- Toolchain: Go 1.27.4 and golangci-lint 2.15.0 are pinned in `mise.toml` next to the LikeC4 tools. `scripts/bootstrap.sh` installs everything on a bare machine. The gate (`mise run check`) runs `fmt lint skipcheck test sshd cover vuln build arch` and fails on a dirty tree. The `sshd` step runs the SSH contract suite against a real `sshd` where one is installed (CI) and says so in one line where it is not (the build sandbox). govulncheck 1.10.0 is pinned there too.
- CI runs the gate on pushes to every branch and on pull requests.
- No credentials are wired and none are needed: the build never deploys and never touches a secret (spec D16).
- Spec status: section 2 is locked from the owner's decisions; section 3 still has INFERRED and TODO rows, each with the phase that must settle it.

## Discoveries

- 2026-11-18 (planning): a cloud session with several repositories starts above the clones and loads no hooks or settings from either repo, so the toolchain is installed by `scripts/bootstrap.sh` at the start of every phase, not by a session hook (spec F14).
- 2026-11-18 (planning): the planning sandbox had no `ssh` or `sshd` binary and no running Docker daemon. Phase 0 decides how the real-`sshd` test lane runs (spec F12, section 7).
- 2026-11-18 (planning): the edge may cut a request whose origin is silent for about 100 seconds, so the default ceiling for a synchronous wait is 60 seconds, not the client's 300 (spec F15, still INFERRED).
- 2026-11-19 (planning): the build was reworked from one run per phase on shared branches to one session that runs the whole roadmap on one working branch per clone, with no phase branches and no merges. Reasons: a session can count on pushing only its own working branch (spec F13), and an idle session's disk is not kept (spec F20). A session can start each clone on a chosen branch (spec F19), so it starts on the plan branch.

- 2026-11-19 (build, Phase 0 premise): the gate is green on the clean tree the session started from (8 seconds), CI is green on the pushed working branch, and pushing the working branch works. The `agency` plugin is loaded (its skills and agents are listed). Whether its changelog and version guard hooks fire in this session was not observed, so their rules are applied by hand: `CHANGELOG.md` is staged with every ship commit, and `git add` and `git commit` are separate tool calls.
- 2026-11-19 (build, Phase 0 premise): the module proxy and the vulnerability database are reachable. There is no Docker daemon. There is no `sshd`, and the session's permission layer refused to install `openssh-server`; the lead did not work around it, so the real-`sshd` lane is CI-only (spec section 7 callout, F12). Adding `openssh-server` to the cloud environment's setup script would give a later session the lane locally.
- 2026-11-19 (build, Phase 0 premise): `scripts/redaction-check.sh` finds the plugin's resolver but the resolver has no term list in this session, so the check prints "no redaction terms configured" and passes. Hygiene is therefore held by rule and by the security lane, not by that script: nothing from the infra clone is quoted here, and fixtures are synthetic.
- 2026-11-19 (build, Phase 0 gate): the first `cover` step summed every line of the profile, and `-coverpkg=./...` writes one copy of each block per test binary, so the total would have fallen as packages were added (a second tested package measured 45.2 percent where the truth was 93.3). It now merges blocks by key. The code-review and QA lanes both found it by counting statements by hand.
- 2026-11-19 (build, Phase 0 gate): advisories that were not applied, each for a reason. Pinning the mise version in CI: `scripts/bootstrap.sh` installs the current mise locally too, so a pin in one place would only make the two differ; pin both together if the operator wants it. Flagging `//go:build` tags on test files in `skipcheck`: no test file has a tag yet; Phase 2 must not use a build tag to keep the real-`sshd` tests out of the local gate without the gate saying so. The remaining simplification options (one `cd` in `check.sh`, default-valued lint settings, the step list repeated in `README.md`) change nothing observable and were left.
- 2026-11-19 (build, Phase 1 gate): four blockers, all fixed in `c92a45f`: a principal with a null value was dropped silently, leaving a tenant nobody maps to; the policy engine allowed zero and out-of-range values; a `known_hosts` file with a certificate-authority line counted as a pinned key; the limit ranges were tested against the table under test. The guard rails were widened and narrowed where the lanes showed cheap bypasses and wrong denials; what a guard rail does not catch is listed in the spec 5.3 callout.
- 2026-11-19 (build, Phase 1 gate): the fix commit made command matching skip quoted text, and the lead's own probe of it found that a quote character in a shell comment or a here-doc body then hid every later line from the command rules (a comment with an apostrophe, then `sudo id` on the next line, was allowed). `9422125` stops quote skipping at a newline, so every line start is a command start again, and adds a fuzz property for it. This is why there are two fix commits in this phase. One probe case is still allowed and is left as a guard-rail limit (spec D6): a command substitution in backticks that holds an unmatched quote, followed by a separator.
- 2026-11-19 (build, Phase 1 gate): not applied, each for a reason. The larger `decode.go` refactor (simplification items 5 and 6): better at a phase start than in a fix commit. A closed set or server-side generation for audit request ids: Phase 5 owns request ids. A test against the `scripts/build.sh` binary: Phase 6 end-to-end tests run the real binary.
- 2026-11-19 (build, Phase 2 premise, done early): F10 was checked against the OpenSSH 7.9 release note and `session.c`. The `signal` request is honoured for command sessions that are not subsystems and not under a forced command, for a fixed list of signal names, and is delivered to the process group. The Go client's `Session.Signal` sends it without asking for a reply, so the SSH layer sends the request itself with want-reply set to learn whether the server accepted it. No kill was found on channel close, so closing is never relied on to stop a command.
- 2026-11-19 (build, Phase 2): F10 is CONFIRMED by observation in CI against OpenSSH 10.2 run as a normal user with a `restrict` key: the `signal` request with want-reply is accepted for `TERM`, `INT`, `HUP`, `QUIT`, `USR1`, `USR2` and `KILL`; `TERM` ends the command and a forked child in its group; a child that called `setsid` survives; a command that traps `TERM` is ended by `KILL` after the grace; a command is still running after the client closes the connection. A root login was not observed.
- 2026-11-19 (build, Phase 2 gate): four blockers, all fixed in `4fe8a13`: a target that authenticated and then stopped answering held `Exec` past every deadline; the host name and port reached an error message that is documented as safe for a tool result; `Download` opened a path before checking its type, so a FIFO hung it; a host key of another type than the pinned one was reported as unreachable instead of a mismatch. Also: `Upload` is now refused inside the SSH layer for a server that does not grant `full`, not only by the policy engine.
- 2026-11-19 (build, Phase 2 gate): observed on both servers and left for Phase 3 to handle: a command whose shell exits while a background child still holds its output keeps the session open until the timeout; the signal is then refused because the shell is gone; the result says the remote process may still be running.
- 2026-11-19 (build, Phase 2 gate): one of the implementer's gate runs after the fix measured 68.1 percent coverage, which is the total with the SSH client's profile missing; it did not reproduce (later runs and CI gave 95.7). INFERRED cause: the lead's own gate was running in the same tree at that moment and both wrote `coverage.out`. If a low total appears with no collision, look at whether `go test` dropped a package's profile.

- 2026-11-19 (build, Phase 3 premise and build): the gate was green on the phase base. F18 (SQLite) is CONFIRMED: both pure-Go drivers build static for linux/amd64 and arm64, run WAL and pass under `-race`; `modernc.org/sqlite` v1.62.0 was chosen (smaller binary, SQLite's own code translated to Go; more modules in the build graph). - 2026-11-20 (build, Phase 3): the container restarted while the implementer was working. The disk, the pushed store commit and the session's scratch files were intact; no engine code had been written yet; the implementer was resumed from its transcript and went on.
- 2026-11-20 (build, Phase 3 gate): three blockers, fixed in `eb3a036`: a start the target never answered was recorded without "may still run"; the data quota was enforced only by the hourly janitor, so a looping caller could fill the disk, and a full disk left ended commands `running` for good; and `Wait` returned a final record before the engine had written `command.finished` and released the slot, which made the package's own tests fail 7 times in 50. Also fixed: one gateway per data directory (a lock file), `Recover` under the engine lock, a kill racing a natural exit, records counted in the quota, waits clamped to `max_wait_seconds`.
- 2026-11-20 (build, Phase 3 gate): the fix made a finishing command wake the janitor, and the lead's re-gate then failed once: a background pass raced a test's own pass on the same record. `30b2ebe` runs one janitor pass at a time and gives the tests a way to wait for a pending pass. The full-disk behaviour is tested with an injected failing store, not a real full file system (a normal user cannot mount one); Phase 6 may try a size-limited directory if the runner allows it.
- 2026-11-20 (build, Phase 3 gate): left for Phase 5, by decision: the engine is not linked into the binary yet; a cap on waiting readers belongs with the HTTP limits; `serve` must not call `Recover` itself (`New` runs it); "shutting down" stays code `internal` with a fixed message; the model's `jobs -> ssh` label still mentions file transfers, which will go from the tools to the SSH layer.
- 2026-11-19 (build, premise for Phases 4 and 5, read early by the lead from the vendors' pages): the Access token's `aud` is an array and its issuer has no trailing slash; signing keys rotate every six weeks with the previous key valid for seven days; the vendor's own Go example uses `go-oidc`. The MCP Go SDK is at v1.8.0, serves the newest protocol revision only in stateless mode, calls `getServer` per request there, and refuses a non-loopback `Host` on a loopback listener unless told otherwise. The client's tool call timeout is 240 seconds, not 300, and the edge's read timeout is 125 seconds by default, not 100; a tunnel buffers a response that is not an event stream. The spec rows are updated in the start commits of Phases 4 and 5.
- 2026-11-20 (build, between Phases 3 and 4): CI failed on the Phase 3 ship commit, which changed only documents. The real-`sshd` contract suite had sent `QUIT` to a command in the instant its shell was replacing itself with `sleep`; `sshd` accepted the request, the command ran its full 300 seconds and exited 0. So "accepted" is not "took effect" for a signal other than `KILL`. The gateway's own stop sequence does not depend on it (`TERM`, then `KILL` after the grace). `0ea2cf2` makes the signal scenarios wait for the remote command to reach a known state first, shortens their sleeps and bounds every wait, and records the observation in the F10 row; CI is green on it with every contract scenario passing against real `sshd`.
- 2026-11-20 (build, Phase 4): the verification library is `go-jose/v4` used directly (no other module comes with it). The vendor's own example library was not chosen: its `nbf` leeway is fixed at five minutes, it does not check `iat`, and its key set refetches without a limit. The vendor's service tokens carry no `nbf`, so `nbf` is required on user tokens and checked only when present on service tokens (F7, spec 5.7 callout).
- 2026-11-20 (build, Phase 4 gate): no blocker. Fixed from the advisories in `296f06a`: the verified claims are now decoded by the library's own decoder (the standard one let `EMAIL` stand in for `email` and took the last of two duplicates; only the issuer could have signed such a token); the user subject is lower-cased so one person is one principal; the middleware no longer trusts an incomplete principal; rejections that happen before a signature is verified are audited one by one only up to 60 a minute and then counted into one summary event, so a flood cannot fill the audit log; keys that could not be refreshed for seven days stop being trusted.
- 2026-11-20 (build, Phase 4 gate): two flaky tests found by the lead's repeat runs. The test issuer freed its port while "down", so a parallel test process could take the port and answer (`236939f`; the same pattern was fixed in two SSH tests and one jobs test with a port that refuses and cannot be taken). The job engine dropped a command's live handle before it released the slot, so a caller could see the command finished and then be told `busy` (`541ceea`).
- 2026-11-20 (build, Phase 4 gate): for the operator guide in Phase 7: any token that carries `common_name` is treated as a service token; whether a client-certificate policy at the edge would also set that claim is not confirmed, so the guide should say to map service principals only for service tokens the operator created.
