# Phase 3 -- security lane report (jobs, store, outputs)

Range `4886053..1b251fa`, read-only. Verdict: **BLOCK** -- 1 blocking, 5 advisory.

## Findings

1. **BLOCKING -- `max_data_bytes` is enforced only by the hourly janitor, so a caller can fill the gateway's disk.** `Sweep` is called only from `janitor()` (`internal/jobs/lifecycle.go:135-147`; `DefaultJanitorInterval` is one hour, `engine.go:68`); `Start` (`engine.go:282-383`) and `run` (`engine.go:459-488`) never look at the tenant's usage. A command stores up to `max_output_bytes` (16 MiB by default) and can finish in under a second, so a model looping `head -c 16M /dev/zero` stores on the order of 100 GiB before the next pass, against a 1 GiB quota. The damage crosses tenants: one disk holds every tenant's output, the database and usually the audit log, and a failed audit write latches the logger broken until restart (`internal/audit/audit.go:154-156`), after which every `Start` and `Kill` is refused (`kill.go:71-73`) while quiet commands run to their timeout. Fix: wake the janitor when a command finishes (a non-blocking send on a one-slot channel after `release()` in `run` and `fail`), so the overshoot is bounded by `max_concurrent_commands x max_output_bytes`; test it by finishing commands past the quota without calling `Sweep`.

2. **ADVISORY -- a live command's record can be rewritten to `lost`, and then cannot be killed.** (a) The exported `Recover` reads `e.started` and unlocks before `RecoverAllTenants` runs (`lifecycle.go:24-30`); a `Start` in that window inserts a running record that the transaction marks lost. (b) `store.Open` (`store.go:100`) takes no lock, so a second process on the same data directory marks the first one's live commands lost. Either way `Kill` returns early because the stored status is not `running` (`kill.go:41`) although a live handle exists. Fix: hold `e.mu` across the check and the store call in `Recover`; take a non-blocking exclusive `flock` on the database file in `store.Open`, held until `Close`; let `Kill` proceed whenever `e.live` returns a handle.

3. **ADVISORY -- `may_still_run` is dropped when `Start` fails after the exec request was sent.** `sshclient.Start` marks that error `mayRun` (`internal/sshclient/command.go:160`, `errors.go:70-72`), but the field has no accessor and `fail` (`engine.go:344-363`) builds the final record without it. A target that takes the request and stops answering leaves a record `error` with `may_still_run` false while the command may be running. Fix: export the flag as a method of `*sshclient.Error` and set `f.MayStillRun` in `fail`.

4. **ADVISORY -- records are outside the quota.** `StoredBytes` sums output only (`store/records.go:413-422`). Command text (up to 64 KiB a record) and zero-byte records (`error` after a refused connection, or the record kept when `command.requested` fails, `engine.go:365-367`) are limited only by `retention_days`. Fix: sum `stored_bytes + length(command)` plus a fixed per-row cost.

5. **ADVISORY -- waits are not clamped in the engine.** `Wait` (`engine.go:583-598`) and `ReadRequest.Wait` (`read.go:78-83`) accept any duration and any number of waiters; the only bounds are the caller's context and the command's own timeout (up to 24 hours). Clamp to `MaxWaitSeconds` here, or put the clamp and a waiter cap in the Phase 5 work order.

6. **ADVISORY -- only the last path element is link-checked, and 5.6 does not say so.** `mkdirPrivate` (`output.go:55-67`) and the orphan sweep (`lifecycle.go:264`) follow a link at `tenants`, `tenants/<tenant>` or `commands`, and `CheckPrivateDir` uses `os.Stat` (`store.go:142`). Planting one needs the gateway's uid or root, which section 6 excludes, but only the 5.4 callout records that. Add the sentence to 5.6, or do every create, read and `RemoveAll` through one `os.OpenRoot` of the data directory.

## Checked, no finding

- **Tenant isolation.** `Insert`, `Get`, `Exists`, `MarkStarted`, `MarkKillRequested`, `MarkMayStillRun`, `Finish`, `List`, `FinishedBefore`, `StoredBytes` and `DeleteFinished` all bind `tenant = ?` (`records.go:168-430`). The cross-tenant pair is in `RecoverAllTenants`: a SELECT with no tenant predicate (`:286`) and an UPDATE keyed by each row's own tenant and id (`:302`); the rows reach only `Engine.Recover`, which writes audit events and returns a count. Every entry point resolves the tenant first (`engine.go:249-255`; empty, malformed or unknown is `not_found`); a missing id and another tenant's id run the same primary-key query and return the same text; the live map is keyed by `(tenant, id)` and the wake-up channels hang off that handle; a cursor carries a position only.
- **Paths.** Ids match `^[a-z0-9][a-z0-9-]{0,62}$` and `^[0-9a-f]{32}$` before `commandDir` joins them; the stream name is a closed set; files are created `O_EXCL|O_NOFOLLOW` 0600 and read `O_NOFOLLOW`; a link or file at `commands/<id>` is refused; a umask can only remove bits; the sweep validates listed names and skips links, and `RemoveAll` does not follow them.
- **Exhaustion.** Storage stops at the limit while writes report success (`output.go:120-160`); `page` cannot overflow and a read allocates at most `max_result_bytes`; slots are taken and released under one mutex with a `sync.Once`.
- **Audit (D12).** Nothing is dialled before `command.requested` is synced, and `Kill` sends nothing before `command.kill_requested`. Events and rows hold counts and a cleaned signal name, never output; command text lives only in the audit log and the 0600 database with its WAL.
- **SQL and input.** Every statement is constant text with bound parameters; the one `Sprintf` formats a compiled-in integer. Cursor, status, stream, signal, limit and ids are validated; no reachable panic found.
- **Crash safety.** Every update has `AND status = 'running'`, backed by a CHECK; a newer schema is refused before WAL mode or a migration; deletion is record first, then directory, with a start-up orphan sweep.
- **Errors (D8).** Engine errors are fixed text; causes stay behind `Unwrap` for `OnError`.
- **Supply chain (D14).** The build graph gains `modernc.org/sqlite` v1.62.0, `libc` v1.80.1, `mathutil` v1.7.1, `memory` v1.12.1, `go-humanize` v1.1.0, `google/uuid` v1.6.0 and `bigfft` (a 2023 pseudo-version; upstream has no tags), matching the implementer report. No cgo; `libc` is `unsafe`-heavy and can spawn `sh` (`system`), unreachable while all SQL is constant. `go.sum` has additions only; `go mod verify` and `govulncheck` are clean; CI, scripts and `mise.toml` are untouched.
- **Hygiene.** Diff, report and commit messages hold only loopback, `192.0.2.1` and `example` names.
