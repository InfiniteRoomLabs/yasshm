# Phase 6 code review -- End-to-end and hardening

Lane: code review (read-only; nothing was run). Range `ce5df4f..a5ea5c9`.

**Verdict: APPROVE.** 0 BLOCKING, 8 ADVISORY.

## What holds

- **Prefilter (`3d22a94`): no counterexample.** Every built-in pattern is a plain concatenation with no `(?i)`, and each `Needs` literal is a required piece of every top-level alternative: `cmd`/`cmdArgs` always emit `(?:word)`, so `\sudo`, `"sudo"`, `'pkexec'`, `/usr/bin/sudo` and every wrapper form still contain the word (`wordQuote` and `pathPrefix` sit around it, never inside it). Checked one by one: `(?:tel)?init` -> `init`; both `rm-root` arms -> `rm`; both `write-to-device` arms end in `blockDev` -> `/dev/`; `dd-to-device` -> `of=`; `pipe-to-shell` and `download-substitution` -> one of `curl|wget|fetch`; `fork-bomb` -> `()`; the alternations of `power-control` and `fs-create` are listed in full. Operator rules have no `Needs` and always run (`policy.go:241`). The filter and the expression see the same trimmed string. The fuzz invariant is a true differential against the unfiltered expression (`fuzz_test.go:35`).
- **Suite.** `test/e2e` imports only test kits (`TestEndToEndImports`; `edgetest` takes one constant from `internal/auth`). All 19 scenarios drive the child over HTTP; the "nothing sent" claims compare the target's request log; expected values are literals. Spec 7's list is covered; the two-tenant substitution is stated and tested.
- **`RLIMIT_FSIZE`.** `prlimit(2)` on a same-uid child needs no privilege; `SIGXFSZ` is `_SigNotify` only in the runtime's table, so it is ignored and the write gets `EFBIG`. It is a real kernel write failure on the open log, equivalent to a full disk for this guarantee. Because the test demands the exact audit message, a regression that acted anyway would not be masked by the database failing under the same limit.
- **Harness.** Build flags equal `scripts/build.sh` (CGO off, `-trimpath`, `-s -w`, the three `-X`). The scanner yields whole lines only; every wait is bounded; cleanups run in the right order; scenarios share nothing but the idle pool of `http.DefaultTransport`. **`Pdeathsig`:** it fires when the creating thread exits, and a Go thread exits only when a goroutine ends while locked to it; nothing in the module or the suite's dependencies calls `runtime.LockOSThread`, so no child is killed early. Do not add `LockOSThread`: it would create that hazard.
- **Gate step.** Count derived from `go test -list`, zero and fewer-than-all fail, the anchored `^--- PASS` ignores subtests, `test` leaves the package out, `pipefail` handled by `|| true` plus the `-lt 1` check. Step list updated in `CLAUDE.md`, `TESTING.md`, `README.md` and the spec callout (`docs/progress.md` is left for the lead, as reported).
- **Test kit move.** Mechanical and behaviour-preserving; `TestTestkitOnlyFromTests` covers the new packages.

## Findings

1. **ADVISORY -- `Needs` is correct today but nothing structural keeps it so** (`internal/policy/commands_test.go:199`). The table test requires cases per rule, not per alternative: adding `|kexec` to `power-control` without a `Needs` entry and without a must-match case passes the gate and silently never matches. Fix: a test that parses each `Pattern` with `regexp/syntax` and computes the required-literal set (concat: any child; alternate: union of all arms; star/quest: none), then asserts every member contains a `Needs` entry.
2. **ADVISORY -- the flake is a test bound, not a product bug** (`internal/testkit/tenanttest/tenanttest.go:29`; `internal/sshclient/command.go:348`). `sendSignal` arms a wall-clock timer of `KillWait`; when it fires it closes the connection and `Signal` reports `ssh_unreachable`, which `Kill` maps to not delivered plus `may_still_run` -- exactly what was seen. `sshtest` answers a signal at once (`kill(2)`, then the reply), so the only way to lose is a round trip slower than one second while every package runs under `-race` on four CPUs. The product is right to treat a reply past the bound as silence (the connection is already closed, and "may still run" is the conservative answer). Fix: `KillWait: 5 * time.Second` in `tenanttest.SSHOptions`, and give the tests that need a short silence bound their own options with the existing `withSSH` (`internal/jobs/engine_test.go:485`, `:503`). The e2e asserts on `SignalDelivered` (`tools_test.go:80`, `commands_test.go:73`) have the same exposure at the product's 2 s default; if one flakes, this is the cause.
3. **ADVISORY -- `TestE2EConfigCheck` has a vacuous case and a misnamed one** (`test/e2e/lifecycle_test.go:243`, `:239`). "a YAML alias" inserts `x: &a 1`: an anchor, on an unknown key, and requires only that stderr contains `x`. It passes if anchors were accepted (`x` is an unknown key) and on almost any error text. Fix: `version: &a 1` wanting `anchors are not supported`, plus an alias case wanting `aliases are not supported`. "a bad host key and a bad limit" changes only the limit: add a malformed `host_key` case or rename. "a missing key file" should want `file does not exist`, not just `private_key_file`.
4. **ADVISORY -- `TestE2EAuditUnwritable` shows less than its comment about later requests** (`test/e2e/audit_test.go:107`). "Refused by the guard (503)" is asserted as `err != nil`, which any protocol error satisfies. Fix: one raw `httpDo` POST through the edge wanting 503. Also, `kill_command` names a finished command (`:63`, `:87`), so "the target saw nothing" is true with or without the failure; use a running command and assert it is still running and no `signal:` request arrived (`TestKillAudit` does this in-process).
5. **ADVISORY -- the "Tokens and key material" row overclaims for key material in errors** (spec line 344). `TestNothingLeaks` covers tokens and the issuer key thoroughly; `TestNoSecretFields` is field names; the only SSH-key evidence named is the happy-path scan of one scenario. Fix: add `internal/config` `TestLoadPrivateKey` (its "garbage content is not echoed" case) to the row.
6. **ADVISORY -- the e2e token scan runs where a leak is least likely** (`test/e2e/tools_test.go:147`). Only `TestE2EEveryTool` scans, and it sends only valid tokens; a token is most likely to be logged on a rejection. Fix: move the `eyJ` and key-line scan into `gateway.cleanup` so every scenario's stderr and audit log are scanned, `TestE2EAuth` included. `eyJ` is adequate (header and payload both start with it).
7. **ADVISORY -- signals by raw pid after the child was reaped** (`test/e2e/harness_test.go:440`, `:489`). `stop()` on a gateway that already exited, and the group check in `cleanup`, address a pid the kernel may have reused; as root in the sandbox that could signal another process. Unlikely, cheap to close: use `g.cmd.Process.Signal` (returns `os.ErrProcessDone`) for the single-process signals.
8. **ADVISORY -- `TestE2EFileSizeLimit` depends on the database staying under the limit** (`test/e2e/audit_test.go:165`). The 128 KiB limit also binds the SQLite files, and "the gateway keeps serving" needs a row insert afterwards. It holds today; a growing WAL or schema would fail it for an unrelated reason. A sentence in the test comment is enough.
