## [Unreleased]

### Added

- Design spec for v0.1 (`docs/superpowers/specs/2026-11-18-yasshm-design.md`): locked decisions, verified external facts, component design, security model, testing and release design, deployment contract, and the phase plan
- `GOAL.md` targeting Phase 0, with a ten-row roadmap, the kickoff prompt and session-start checklist for one orchestrating cloud session that holds two repositories, and the hard limits of the build (no deploy, no real host, no secret)
- Phase work orders for the four-lane review gate (`docs/phases/_templates/{implementer,code-review,simplify,security,qa}.md`)
- LikeC4 model of the planned gateway (`docs/architecture/`): the MCP client, the identity-aware edge, the SSH targets, and the ten yasshm components and datastores, each tagged `#planned` until its phase builds it
- `scripts/bootstrap.sh`: installs mise and the pinned toolchain on a bare machine; idempotent
- Go 1.27.4 and golangci-lint 2.15.0 pinned in `mise.toml`
- Go module `github.com/InfiniteRoomLabs/yasshm` with `cmd/yasshm` with `version` and `help` subcommands (version, commit and build date injected at build time); standard library only
- The full gate in `scripts/check.sh`: `fmt`, `lint` (`.golangci.yml`), `skipcheck`, `test` (`-race -shuffle=on`, coverage profile), `cover` (floor 85 percent, `internal/testkit` excluded), `vuln` (govulncheck pinned in `mise.toml`), `build`, `arch`
- `mise run build` (`scripts/build.sh`: linux amd64 and arm64, `CGO_ENABLED=0`, `-trimpath`, `dist/SHA256SUMS`), `mise run test`, `mise run lint`, `mise run fuzz` (`scripts/fuzz.sh`)
- `mise run build` is reproducible: the build date is `SOURCE_DATE_EPOCH` or the commit time, and a `VERSION` override is validated
- CI ensures `sshd` is installed on the runner and fails if it is not; `scripts/bootstrap.sh` and the gate report whether `sshd` is present locally (the real-sshd lane is CI-only, spec section 7)
- `internal/tenant`: the shared domain types (`TenantID`, `ServerID`, `CommandID`, `Principal`, `AccessLevel` ordered none < look < full, `Server` with `IdentityFor`, `Identity`, `PrincipalMatch`, `Policy`, `Limits`); `tenant.Permits` is the one place access levels are compared
- `internal/config`: strict loading of the YAML config (spec 5.1) with every problem reported in one pass as `path.to.key: message (line N)`, the limits table with defaults, allowed ranges and cross-field rules, `MaxTenants = 1`, and private key and known_hosts checks that never echo key material
- `internal/policy`: `Engine.Decide` with the `not_found`, `access_denied` and `policy_denied` checks in order, the built-in command and path denylists with a named rule per entry, and the operator's `deny_commands` and `deny_paths`
- `internal/audit`: the append-only JSONL audit log (`O_APPEND`, mode 0600, one write and one sync per event, UTC timestamps), a typed constructor for every event of spec 5.4, and `Logger.Before` for audit-before-act
- `yasshm config check --config <file>`: exit 0 when valid, 1 with the problem lines, 2 for a usage error
- Fuzz targets for the config decoder and the command and path guard rails; `internal/deprule` enforces the package dependency rule of spec section 4; `internal/testkit/configtest` writes synthetic configs for tests
- Dependencies: `go.yaml.in/yaml/v3` v3.0.6 and `golang.org/x/crypto` v0.59.0
- `internal/keyfile`: reads a private key file once and checks the open file (regular, no group or other bits, owned by the effective uid, at most 64 KiB); the config loader uses it and the SSH layer will
- Path globs (built-in and `deny_paths`) take `**` as the whole first element (any depth) or last element (a subtree); new built-in path rule `proc-links` and wider credential, key and shadow-backup entries
- `internal/deprule` also checks that `internal/testkit` is imported only from `_test.go` files
- `internal/sshclient` (Phase 2): `Client.Start` returns a `Command` handle with `Wait`, `Signal` and `Close`; `Exec`, `Download`, `Upload` and `Probe`; one connection per call, every call scoped by `TenantID`; host keys pinned (never a certificate, never trust on first use), the private key read through `internal/keyfile` at each connect, no PTY, environment, agent or forwarding, stdin closed; a context end sends `TERM`, waits the kill grace, sends `KILL`, and only then closes, and `ExitStatus.MayStillRun` says when no exit arrived; `Signal` sends the request with want-reply and reports a refusal; errors carry one of `ssh_unreachable`, `ssh_auth_failed`, `host_key_mismatch`, `timeout`, `internal` and the server id, in fixed text that never names the host, port, user, key path or file mode
- `internal/hostkey`: the host key pinning rules, shared by the config loader and the SSH layer
- `internal/testkit/sshtest`: an in-process SSH server that runs commands with `sh -c` in their own process group, honours `signal`, serves SFTP, records every request and has fault switches (wrong host key, refused key, dropped connection, refused signal, slow banner, no exit status)
- `internal/testkit/realsshd`: starts a real OpenSSH `sshd` as the current user on a loopback port with a `restrict` key; the SSH contract suite runs against both servers, and the real-`sshd` half observed F10 in CI (the `signal` request is accepted and reaches the process group)
- The gate step `sshd` between `test` and `cover`: runs the real-`sshd` tests where `sshd` exists and fails unless one passed; CI sets `YASSHM_REQUIRE_SSHD=1` so a missing `sshd` fails
- Dependency: `github.com/pkg/sftp` v1.13.12 (with `github.com/kr/fs` v0.1.0)
- `sshtest` switches for a server that never answers `signal`, `exec` or a channel open, and one that refuses SFTP; `realsshd` tags every session with an environment marker so the suite asserts no process is left behind on either server
- `internal/store` (Phase 3): command records in SQLite through the pure-Go driver `modernc.org/sqlite` v1.62.0 (spec F18): WAL mode, one writer, busy timeout, `synchronous=FULL`, a forward-only migration list versioned by `PRAGMA user_version`, a database newer than the binary refused before any write, `(tenant, id)` primary key with every index and every statement scoped by tenant, a state machine in which only `running` changes and `lost` is reached only by `RecoverAllTenants`, the database 0600 inside a 0700 data directory owned by the gateway's user
- `internal/jobs` (Phase 3): the job engine -- `Start` (validate, reserve a slot or return `busy` naming `max_concurrent_commands` or `max_concurrent_per_server`, insert, write `command.requested` before connecting, start), `Wait`, `Get`, `List` (newest first, filters, opaque cursor), `Kill` (`TERM`, `INT`, `KILL`; `command.kill_requested` before the signal; idempotent on a finished command), `ReadOutput` (offset from the start or the end, `next`, `eof`, a wait woken by the capture writer), `Recover`, `Shutdown` and the janitor (`retention_days`, then `max_data_bytes` oldest first); commands run under engine-owned contexts; every status of spec 5.6 is reached against the in-process SSH server, including the background child that keeps the session open (`timed_out`, `may_still_run`)
- Output files under `data_dir/tenants/<tenant>/commands/<id>/` (directories 0700, files 0600, `O_EXCL|O_NOFOLLOW`), `merge_stderr` by default, storage stopped at `max_output_bytes` while the remote side keeps draining; a fuzz target for the paging arithmetic
- Dependency: `modernc.org/sqlite` v1.62.0 with `modernc.org/libc` v1.80.1, `modernc.org/mathutil` v1.7.1, `modernc.org/memory` v1.12.1, `github.com/dustin/go-humanize` v1.1.0, `github.com/google/uuid` v1.6.0, `github.com/remyoudompheng/bigfft` (build graph); `internal/deprule` covers `store` and `jobs`
- `internal/auth` (Phase 4): the `Authenticator` interface and its Cloudflare Access implementation -- reads only `Cf-Access-Jwt-Assertion` (one value, at most 16 KiB), accepts RS256 only (refused before any key lookup otherwise), requires a `kid` in the key set, checks the signature, `iss` (`https://<team_domain>` exactly), `aud` (string or array) and `exp`, `nbf`, `iat` with 30 seconds of leeway, and maps `email` (a user) or `common_name` (a service token) to the one tenant whose `principals` admit it; every rejection is an `auth.Error` with a reason from a closed set
- The key set: fetched at `Start` without blocking, refreshed hourly (a minute after a failure), refetched on an unknown `kid` at most once a minute with concurrent callers sharing one fetch; 10 s timeout, 1 MiB cap, JSON content type, same-host https redirects only, no cookies, cancelled by `Close`; a failed fetch keeps the last good keys; `Ready` and `Status` for `/healthz`
- `auth.Middleware`: a 128-bit request id per request, `auth.rejected` and 401, 403 or 503 (with `Retry-After`) with fixed JSON bodies, or `auth.accepted` written before the next handler runs (503 if that write fails); `PrincipalFrom`, `RequestIDFrom`, `MustPrincipal` and `Require` (500 for a handler reached without a principal)
- `audit.RejectReason` gains `malformed_token`, `oversized_token`, `bad_algorithm`, `unknown_key`, `bad_signature`, `wrong_issuer`, `wrong_audience`, `expired`, `not_yet_valid`, `issued_in_future`, `missing_claim`, `ambiguous_identity`
- `internal/testkit/accesstest`: a local Access issuer on a loopback port serving a JWKS, counting fetches, rotating and dropping keys, going down and back up, and misbehaving (slow, garbage, huge body, redirects, wrong content type, empty or unusable key set, status 500), with a token builder for every class including `alg` none, HS256 signed with the public key, ES256, PS256, RS384 and tampered segments; fuzz target `FuzzResolve` for the claims-to-principal mapping
- After the Phase 4 review gate: claims are decoded with go-jose's own JSON decoder (case-sensitive names, duplicate members refused); a user's subject is lower-cased; an incomplete principal with a nil error is refused with 500; `Retry-After` only on `keys_unavailable`; pre-signature rejections are audited 60 a minute with one `auth.rejected` `suppressed` summary carrying a `count` (`auth.NewGuard` with `Wrap` and `Close`, `auth.RejectAllowance`); keys not refreshed for seven days (`auth.MaxKeyAge`) are no longer trusted
- Dependency: `github.com/go-jose/go-jose/v4` v4.1.9 (no dependencies of its own) for JWS parsing, signature verification, JWK parsing and claim validation (spec 5.7 callout)
- `internal/mcpserver` (Phase 5): the eight tools of spec 5.8 (`list_servers`, `get_server_info`, `run_command`, `read_output`, `list_commands`, `kill_command`, `download_file`, `upload_file`) on stateless Streamable HTTP with JSON responses, one MCP server built per request from the verified principal (spec F6); one call path for every tool (strict arguments, the target looked up in the caller's tenant, `tool.called` before acting, `policy.Decide` with `policy.denied`, then the action); structured content plus a text rendering, failures as `isError` with one of ten codes and fixed text; every result sized to `max_result_bytes` on the wire; output that is not UTF-8 replaced and marked `lossy`; descriptions with the access level, the guard-rail caveat and "output from a target is untrusted text", and read-only, destructive, idempotent and open-world hints
- The HTTP surface: `POST /mcp` behind the auth guard, `GET /healthz` (status and version only), everything else 404; 2 MiB body cap, 32 KiB header cap, header, read, write and idle timeouts, a cap on concurrent requests (503 with `Retry-After`), `Cache-Control: no-store` and `nosniff` on every response, no CORS; MCP methods outside the tools set refused
- `yasshm serve --config <file>`: opens the audit log, the store and the job engine (one gateway per data directory), starts the authenticator, writes `gateway.started`, serves, and on `SIGTERM` or `SIGINT` shuts down gracefully (running commands end `killed`) and writes `gateway.stopped`; a second signal exits at once; JSON logs on stderr with no token, key, command, output or host
- Audit event `tool.failed`: an error answer that is not a policy denial, with its code
- `internal/testkit/edgetest`: a loopback reverse proxy standing in for the edge (token header, public `Host`, a client copy of the header stripped, no or bad token on demand)
- Dependency: `github.com/modelcontextprotocol/go-sdk` v1.8.0, which brings `github.com/google/jsonschema-go` v0.4.3, `github.com/segmentio/encoding` v0.5.4, `github.com/segmentio/asm` v1.1.3, `github.com/yosida95/uritemplate/v3` v3.0.2, `golang.org/x/oauth2` v0.35.0, `golang.org/x/sync` v0.24.0 and `golang.org/x/time` v0.15.0 into the build graph
- `test/e2e` (Phase 6): the end-to-end suite builds the real binary once per run with the flags of `scripts/build.sh` and drives `yasshm serve` as a child process (port 0, its own data directory, audit log, config and keys) with the MCP Go SDK client through the stand-in edge; 19 scenarios cover spec section 7's list (every tool, no token / bad token / unmapped principal, the HTTP surface, `/healthz`, a long command paged and killed, a timeout, output past `max_output_bytes`, `busy`, policy denials, a host key mismatch, `upload_file` denied, an audit log made unwritable under the running binary, `SIGKILL` then `lost`, graceful shutdown, `config check`, a second gateway, two tenants refused, a 200-call burst with descriptor and RSS bounds, and an output file that cannot grow)
- The gate step `e2e` after `sshd`: runs the suite (test process under `-race`) and fails unless every top-level `TestE2E*` that `go test -list` names passes; the `test` step leaves `./test/e2e` out
- Spec section 6 names the tests behind each guarantee and the files that state each "not guaranteed" item; `internal/deprule` `TestSecurityModelTable` fails when a named test or phrase is missing, and `TestEndToEndImports` holds the suite to the test kits
- `internal/testkit/audittest`, `tenanttest` and `syncbuf`: test support the job engine, endpoint, auth, `serve` and `cmd` tests had copied from each other; `accesstest`'s `Issuer.For`
- `BenchmarkDecideMaxCommand` and `BenchmarkCommandRules` measure the command rails on a 64 KiB command

### Changed

- Phase 6 review gate: a rejected token with a bad signature counts against the per-minute allowance of unverified rejections, and rejections of a token whose signature verified (expired, another audience, unmapped principal, ...) have their own allowance of 60 a minute with their own `suppressed` summary (`stage` `unverified` or `verified`); every request is still answered, and `auth.accepted` is never suppressed
- Probes and file transfers take a per-server slot (`max_concurrent_per_server`, `busy` over it); the per-principal share of the request cap is taken before the body is read
- The config file and a `known_hosts_file` are refused when group or other can write them, and the audit log when its directory is writable by group or other
- `serve` ignores `SIGHUP` with one log line and warns at start when `certs_url` is set; `go.mod` names Go 1.27.4 and `scripts/build.sh` clears `GOFLAGS`
- The end-to-end suite: a scenario table tied to spec section 7 (`TestScenarioTable`, required by the `e2e` step), an audit failure at `command.requested`, `SIGHUP`, a token and key scan after every scenario, and an output-limit scenario that no longer depends on which stream arrives first; `TestNeedsAreRequired` derives each policy rule's required literals from its pattern; the test SSH options wait 5 seconds for a signal's answer
- The spec and README list another local user taking the loopback port while the gateway is down as not guaranteed; section 8 asks for a gateway host with no untrusted local users
- The command rails skip a built-in rule whose literals (`Needs`) are absent from the command: an allowed 64 KiB command is decided in 0.1 to 0.5 ms instead of 0.25 to 0.44 s, with no decision changed (spec 5.3 callout); the worst case, a command that holds every rule's literal, stays about 0.26 s
- README lists what v0.1 does not guarantee (spec section 6)
- Phase 5 review gate: a tool error carries no structured content, only one text block of one-line JSON `{code, message, rule?}`, so a schema-validating client sees it; target output and file data are text blocks of their own after the gateway's header block; JSON-RPC batches are refused (400) and a per-request server serves one `tools/call`; `run_command` and `read_output` count the wait from the request's arrival, and a caller that goes away ends the wait on every protocol version (audited `client_closed`, not a failure); one principal holds at most three quarters of the request cap; shutdown waits for probes and file transfers in flight so `gateway.stopped` is last; unvalidated ids and enums are audited as `(invalid)` and long command and path text is cut; a server outside the caller's tenant is refused before the policy engine; `list_commands` never hides a command; `download_file` returns base64 for any chunk that is not valid UTF-8 as it stands; a signal during start-up exits cleanly; new config rule `max_wait_seconds + 2 x connect_timeout_seconds <= 120`, `connect_timeout_seconds` at most 59; the key set fetch logs its result before it releases its waiters (a test read the log empty once)
- The allowed maximum of `default_wait_seconds` and `max_wait_seconds` is 110 (was 290), under the edge's 125-second proxy read timeout and the client's 240-second tool-call limit; the minimum of `max_result_bytes` is 4096 (was 1024)
- The architecture model has `yasshm.tools` and `yasshm.http` built, a `tools -> ssh` relationship for file transfers and the probe, and labels that match the code
- The SSH contract suite signals a command only after it printed a marker from a process that is not the login shell (bash ignores `SIGQUIT` and drops one that arrives before its `exec`), uses `sleep 30` and bounds every `Wait` to 10 seconds; spec F10 and 5.5 record that an accepted signal is not one that took effect
- Phase 3 review gate: a command is reported finished only after its record, its `command.finished` event and its slot release; a start the server never answered records `may_still_run` (`(*sshclient.Error).MayStillRun`); a finishing command wakes the janitor and `Start` is `busy` with `max_data_bytes` at the quota, which now also counts command text and 256 bytes per record; a failed end write is retried, kept in memory and written by the janitor, and the janitor deletes an output directory first when a record cannot be deleted on a full disk; one gateway per data directory (`flock` on `yasshm.lock`); `Recover` cannot race a first `Start`; `Kill` signals any live command and a kill racing a natural exit is not counted; no second `command.finished` for a record that had already finished; waits capped at `max_wait_seconds`; a migration refuses a newer database found inside its transaction; `sshtest` answers `exec` before streaming; shared test support in `internal/testkit/leakcheck` and `sshtest.KeyLine`
- A command with a live handle in the job engine is reported running until its slot is free, whatever its stored status
- Janitor passes run one at a time, and the job engine tests wait for a pending finish-triggered pass before they change the clock or the janitor's hooks

- Phase 1 review gate: null or empty principals and a tenant without a valid principal are errors; ASCII-only emails with ASCII case folding; `known_hosts_file` refuses `@cert-authority` lines and needs one key that is not revoked; `deny_commands`/`deny_paths` capped at 256 entries; `max_upload_bytes` maximum lowered to 1048576
- Phase 1 review gate: policy fails closed on zero and undefined values (`Permits` outside `none..full`, a tool requiring `none`, a principal without tenant or kind, an empty tenant id); command rails skip quoted text, cover `eval`, `-exec`, `|&`, quoted or escaped command words and targets, more shells, and stop denying `command -v`, `| python3 -m ...` and `&&` inside functions
- Phase 1 review gate: the audit log ends a partial last line on open, refuses a non-regular path before opening and a log owned by another uid, stores `&`, `<`, `>` literally, refuses an unnamed event, and takes a closed set of stop reasons
- Command rails skip a quoted span only when it opens and closes on one line, and every line start is a command start, so a quote in a comment or here-doc cannot hide a later line
- `mise run fuzz` passes `-fuzzminimizetime 1s` so the 30 seconds go to fuzzing, not minimizing
- The `known_hosts` and pinned-key rules moved from `internal/config` into `internal/hostkey`, with the same messages; a `known_hosts` file is now opened with `O_NONBLOCK`, so a FIFO cannot block the loader; a file whose lines for the server are all certificates gets its own message
- Phase 2 review gate: no SSH wait is unbounded (the exec reply by the context plus the connect timeout, every signal reply by the kill grace or kill wait, then the connection is closed and the status says the command may still run); `Error()` is fixed text without host, port, user, uid, mode or path; a server offering no pinned key type is `host_key_mismatch`; `ssh_auth_failed` only after the host key was accepted; the client refuses a level the server does not grant (`Upload` needs `full`); `Download` refuses a FIFO or device before opening it and reads size-0 files (procfs) to EOF; server signal names are checked; exit 0 with a failed writer is reported as such; the `sshd` gate step requires every in-process contract scenario to pass against real `sshd` as well; a partial upload stays when the connection is gone (documented, not removed)

- `GOAL.md` targets Phase 6; `docs/progress.md` records Phases 0 to 5 as shipped
- A dirty working tree now fails the gate (`scripts/check.sh` exits 1) instead of printing a banner
- `TESTING.md`, `CLAUDE.md` and `README.md` describe the gate as it now is
- Template placeholders replaced with the project's name and description in `README.md`, `CLAUDE.md`, `AGENTS.md`, `TESTING.md`, `docs/progress.md` and the architecture workspace; the "Using this template" checklist is done and removed
- `CLAUDE.md` is now the yasshm rulebook: one working branch per repository with a phase as a commit range on it, the two-repository rules, the hard limits, and the cloud-session gotchas
- CI runs the gate on pushes to every branch, not only `main` and pull requests
